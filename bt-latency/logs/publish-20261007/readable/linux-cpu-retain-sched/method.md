# CPU reductions with Linux scheduling retained

All runs use the physical S31 and basedsurface BlueZ peer, LE 1M. The accepted settings are retained: HZ=100, bt_worker_cpu=-1, ordered high-priority radio workqueue, BTstack CPU1/RR20, direct HCI, 10 controller TX buffers, HCI rings 32/16, BT tick 40 ms, sleeping gate, burst 24, local callbacks, no BTstack wake coalescing, BLE value 495 bytes / 15 ms, SPP frame 990 bytes. No emulator, scheduler replacement, ASID change, permanent init_mm borrowing or persist write.

The candidate has independent root-only runtime controls, with lazy enabled by default in the revised image, for lazy userspace HWLoop/PIE first use, empty-waitqueue wake suppression in BT-only mode, and coalesced immediate ordered-workqueue notifications in BT-only mode. mod_delayed_work promotes pending delayed work; a full-barrier atomic exchange consumes the token before event examination. wq_has_sleeper provides the publication barrier before skipping an empty queue.

The first-use flag resets on exec/handler setup, copies on fork, activates on signal-context restore only for live/dirty saved state, and records dirty eager-mode state before a runtime switch to lazy. Unsupported vendor instructions retry once before normal SIGILL. Existing unsupported PIE migration is preserved. First-use activation precedes that check so an OFF HWLoop instruction remains on CPU0; a u16 prefix read supports two-byte alignment. CPU bring-up and resume discard firmware-owned coprocessor state into a per-CPU scratch buffer, preserving the task context, because OpenSBI starts PIE enabled. Eager/lazy real instruction and context test results are compared before throughput measurements.

CPU is elapsed wall time minus NO_HZ idle/iowait residency, divided by two-core capacity. Each checked 40-second host-received transfer contains a quiet 30-second CPU window starting five seconds after first payload. The probe also enables extension diagnostics for a separately timestamped window enclosing the CPU sample, freezes them, and reads totals after disabling. No UART output occurs in the window.

Extension timings surround the actual suspend/restore functions at BTstack syscall trap entry / final user return (regs->cause=EXC_SYSCALL, task comm prefix s31-btstack). Boundaries run with local interrupts disabled, so time cannot include sleeping or migration. Timing includes the function, SBI and timer/counter instrumentation; it excludes IRQ transitions and other tasks. TIME ticks use the built DT's 320 MHz timebase. A back-to-back timer calibration is retained per measured suspend. Frozen RV32 64-bit counters are read outside the window. IRQ and generic syscall dispatch time are not assigned to this category.

Same-image A/B has identical instrumentation and scheduler settings. A later diagnostics-disabled check is needed before interpreting a retained production gain. Raw commands, UART, host payload, counters, firmware bindings, patch and scratch-byte matches are retained. Rates are end-to-end host FD, not pump-to-controller.

The initial-image eight runs retain exploratory timings. A host rebuild overlapped part of the first BLE series; those CPU/throughput values are not the final optimization acceptance comparison. The revised-image symmetric baseline/lazy/all/all/lazy/baseline comparison runs after all builds finish, with two samples per condition and protocol. Initial-off, signal-handler return to an unused task, active-context saving, exec reset and two-byte-aligned instruction/CPU0-affinity tests run before this comparison.
