# Host build-environment fixes (BasedSurface, NOT repo changes)

Both are host-only; no repo/submodule files modified. Needed for any
`make build` rerun on this host. `git -C u-boot-esp32-s31 status` stays clean
(SWIG fix lives in `out/`, which is gitignored).

1. setuptools missing for U-Boot pylibfdt (`from setuptools import setup`
   → `ImportError`, system setuptools is a stub without `__version__`):
   `python3 -m pip install --user --break-system-packages "setuptools>=70"`
   (installed setuptools-84.0.0 to `~/.local`). Persists across builds.

2. `S31_ALLOW_UNPINNED=1` in `local.mk` is NOT forwarded to the
   firmware/radio sub-make (`firmware/radio/Makefile:84` honors the
   variable, but `local.mk` values are not exported down that chain;
   `mk/radio.mk:6` only covers its own check). Symptom: radio
   `idf-check` fails with `IDF revision 08e0d30a… differs from pinned
   a602e67b…` even with `local.mk` set. Invoke builds as
   `S31_ALLOW_UNPINNED=1 make …` (command-line variables propagate to all
   sub-makes). Combined invocation used here:
   `PATH="$HOME/.local/bin:$PATH" S31_ALLOW_UNPINNED=1 make build`.

3. SWIG 4.3.0 generator bug vs its own runtime: U-Boot v2024.07
   `scripts/dtc/pylibfdt` wrapper generated by host `swig` 4.3.0 emits 2-arg
   `SWIG_Python_AppendOutput(resultobj, val|buff)` at 6 call sites, but the
   4.3.0 runtime header declares the 3-arg form `(result, obj, is_void)`
   (other call sites in the same file correctly pass `, 0`). Upstream fixed
   the generator in 4.3.1. A plain `sed` of the wrapper does NOT stick:
   U-Boot's `rebuild` target regenerates it every build. Fix: PATH shim at
   `~/.local/bin/swig` (host-only, not in repo) that delegates to
   `/usr/bin/swig` then appends `, 0` (`is_void=0`; these sites append real
   values, matching the sibling 3-arg sites) to the generated file. Invoke
   builds as `PATH="$HOME/.local/bin:$PATH" make …`. Only Ubuntu 25.10's
   swig 4.3.0-2 is available (`apt policy swig`); no repo/submodule files
   touched (`git -C u-boot-esp32-s31 status` clean; fix point is outside
   both source and `out/`).
