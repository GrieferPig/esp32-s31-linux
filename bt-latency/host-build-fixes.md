# Host build-environment fixes (BasedSurface, NOT repo changes)

Both are host-only; no repo/submodule files modified. Needed for any
`make build` rerun on this host. `git -C u-boot-esp32-s31 status` stays clean
(SWIG fix lives in `out/`, which is gitignored).

1. setuptools missing for U-Boot pylibfdt (`from setuptools import setup`
   → `ImportError`, system setuptools is a stub without `__version__`):
   `python3 -m pip install --user --break-system-packages "setuptools>=70"`
   (installed setuptools-84.0.0 to `~/.local`). Persists across builds.

2. SWIG 4.3.0 generator bug vs its own runtime: U-Boot v2024.07
   `scripts/dtc/pylibfdt` wrapper generated by host `swig -version 4.3.0`
   emits 2-arg `SWIG_Python_AppendOutput(resultobj, val|buff)` at 6 call
   sites, but the 4.3.0 runtime header declares the 3-arg form
   `(result, obj, is_void)` (other call sites in the same file correctly
   pass `, 0`). Upstream fixed the generator in 4.3.1. Fix applied to the
   OUT-TREE file only:
   `out/u-boot/scripts/dtc/pylibfdt/libfdt_wrap.c`, appending `, 0`
   (`is_void=0`; these sites append real values, matching the sibling
   3-arg sites). distutils only regenerates when `libfdt.i` is newer than
   the wrapper, so the sed survives incremental rebuilds; re-apply if the
   `.i` is ever touched (symptom: same `SWIG_Python_AppendOutput` arity
   error returns).
