ESP32-S31 OpenSBI Flash XIP layout

Goal:
- Keep OpenSBI text/rodata in flash and execute through the flash MMU window.
- Keep OpenSBI writable data, BSS, scratch, stack, and heap in a 64-KiB
  internal HP-SRAM carve-out so Linux can use all 16 MiB of cached PSRAM.
- Keep the OpenSBI partition size fixed at 512KB.
- Boot OpenSBI/Linux on HP core 1. Core 0 boots the ESP-IDF factory app in
  single-core mode and keeps running the FreeRTOS scheduler.

Address contract:
- The factory app maps the complete 16-MiB Flash linearly at 0x40000000.
- OpenSBI is at flash offset 0x220000 and must be linked with
  FW_TEXT_START=0x40220000.
- OpenSBI writable sections are linked with FW_RW_START=0x2F052000.
- OpenSBI owns the 64-KiB internal HP-SRAM interval
  0x2F052000..0x2F062000. The factory app reserves it before heap creation.
- Linux receives the full 16-MiB cached PSRAM alias in its DT memory node:
  0x50000000..0x51000000.
- ESP-IDF maps PSRAM at the cached 0x50000000 alias, but the factory app uses
  CONFIG_SPIRAM_USE_MEMMAP and explicitly disables USE_CAPS_ALLOC/USE_MALLOC.
  IDF's own extram reserved-region entry therefore keeps all PSRAM out of the
  FreeRTOS heap without a duplicate project reservation.
- Linux xipImage is at flash offset 0x400000 and executes at 0x40400000,
  aligned to the 4-MiB Sv32 megapage boundary. Its partition reserves exactly
  0x600000 bytes and ends at flash offset 0xA00000.
- The persist partition starts immediately after OpenSBI at flash offset
  0x2A0000 and fills the 0x160000 gap before Linux. It is a 1.375-MiB data
  partition and ends at the Linux offset.
- The rootfs starts at flash offset 0xA00000 and executes at 0x40A00000. Its
  partition is expanded to 0x600000 bytes and ends at the 16-MiB flash limit
  (offset 0x1000000).
- The full 16-MiB Flash MTD window is the same linear mapping,
  0x40000000..0x41000000.

Partition image format:
- Offset 0: raw OpenSBI fw_jump.bin.
- Next byte after fw_jump.bin: OpenSBI FDT blob.
- Padding: zero bytes up to partition_size - 4.
- Last 4 bytes of the 512KB partition: little-endian uint32 file offset of the FDT blob.

Boot flow:
- The ESP-IDF second-stage bootloader uses the normal IDF partition selection
  and boots the factory app on core 0.
- The factory app is built with CONFIG_FREERTOS_UNICORE=y and
  CONFIG_ESP_SYSTEM_SINGLE_CORE_MODE=y, so IDF does not start core 1.
- The factory app verifies PSRAM, maps OpenSBI/Linux and the rootfs flash
  window, configures permissive APM/MSPI PMS, rewrites the shared 64-KiB PSRAM
  MMU entries for the 16-MiB cached window, enables hart1's private I-cache
  bus and the shared D-cache bus, then writes the core 1 boot address.
- Core 1 starts in a small IRAM trampoline. The trampoline clears interrupt
  state, installs hart-local PMA entry 7 for the cached 64-MiB PSRAM aperture,
  installs a full-space PMP entry for Linux S-mode, and jumps to OpenSBI with:
  - a0 = 1
  - a1 = fdt_addr
- Core 0 remains in the FreeRTOS scheduler after releasing core 1. Its worker
  task and timer interrupts are used to verify concurrent scheduler progress.
- OpenSBI owns 0x2F052000..0x2F062000 (64 KiB) of IDF-usable HP SRAM.
- Linux devices own a contiguous 0x6880-byte HP-SRAM carve-out:
  0x2F072F80..0x2F075F80 for AXI-GDMA descriptors,
  0x2F075F80..0x2F076F80 for AHB-GDMA descriptors,
  0x2F076F80..0x2F076FC0 for USB local SRAM, and
  0x2F077000..0x2F079800 for the UHCI0 payload ring. The factory app
  registers the combined interval with SOC_RESERVE_MEMORY_REGION before heap
  creation.
- AXI-GDMA, SDMMC, Ethernet, and USB OTG are enabled. Their DMA allocations
  use cached Linux memory plus the existing S31 driver cache-maintenance and
  internal-SRAM descriptor/status carve-outs.

Hart1 cached-PSRAM requirement:
- PMA is hart-local; copying hart0's shared MMU/APM/cache registers is not
  sufficient. ESP-IDF's S31 esp_cpu_configure_region_protection() programs
  PMA entry 7 as a locked RWX NAPOT region for
  0x50000000..0x53FFFFFF. The hart1 trampoline must do the same.
- The corresponding CSR values are pmaaddr7=0x147FFFFF and
  pmacfg7=0xE000001D. Without this entry, hart1's first store to cached PSRAM
  stops with a PMP/PMA Store access fault even though MMU, APM and MSPI PMS
  allow the access.
- Linux setup_vm() builds Sv32 page tables in cached PSRAM. S31's page-table
  walker does not snoop the shared write-back D-cache, so head.S writes back
  the cached PSRAM window before loading SATP.

OpenSBI requirements:
- fw_jump.S must report boot hart 1.
- fw_base.S must allow hart 1 through the early entry check.
- The OpenSBI/Linux FDT CPU node must describe cpu@1/reg=<1> for the single
  Linux hart.

Build-time checks:
- The generated fw_payload.bin must be exactly 512KB.
- OpenSBI + FDT must fit in the first 512KB - 4 bytes.
- Link-time assertions require FW_TEXT_START=0x40220000,
  FW_RW_START=0x2F052000, and writable sections no larger than 16 KiB. The
  configured 8-KiB stack/scratch area and 37-KiB heap keep the total runtime
  allocation within the 64-KiB reserved interval.

OpenSBI XIP relocation rule:
- fw_base.S copies .data from flash LMA to FW_RW_START before the boot lottery.
- The R_RISCV_RELATIVE relocation loop then patches pointers inside .data, for
  example platform.ops at platform + 0x60.
- Do not copy .data a second time after relocation. Doing so restores the raw
  flash image, zeros relocated pointers, and can fault on a null load in
  sbi_platform_ops().

Early fault note:
- OpenSBI's first instructions copy .data from flash LMA to FW_RW_START.
- A store/AMO access fault before the OpenSBI banner usually points at the
  HP-SRAM reservation or handoff protection state, not the FDT offset.
