ESP32-S31 OpenSBI / Linux XIP 当前布局
======================================

本文只记录当前实现。旧的“hart1 是启动 hart、hart0 永久停驻”方案已经废弃。

1. Flash 与运行时地址
---------------------

- loader 将板载 16 MiB Flash 线性映射到 0x40000000..0x41000000。
- OpenSBI 分区：Flash offset 0x220000，大小 0x80000；
  FW_TEXT_START=0x40220000，代码和只读数据直接从 Flash XIP。
- persist 分区：offset 0x2a0000，大小 0x160000。
- Linux xipImage：offset 0x400000，大小上限 0x600000；执行映射从
  0x40400000 开始，满足 Sv32 4 MiB megapage 对齐要求。
- rootfs：offset 0xa00000，大小 0x600000；线性 Flash 地址为
  0x40a00000..0x41000000。

OpenSBI 可写区的 FW_RW_START=0x50ff0000。它独占 cached PSRAM 的最后
64 KiB，即 0x50ff0000..0x51000000；设备树必须把该区标为 no-map，Linux
不得分配它。

2. fw_payload.bin 格式
----------------------

- offset 0：原始 OpenSBI fw_jump.bin。
- fw_jump.bin 之后按 8 字节对齐放置 FDT。
- 中间补零到分区末尾前 4 字节。
- 512 KiB 分区最后 4 字节：FDT 文件偏移的小端 uint32。

构建必须检查：成品恰为 0x80000 字节；OpenSBI 与 FDT 不得覆盖最后的
偏移槽；链接断言保证所有 writable section、stack、scratch 和 heap 均落在
上述 64 KiB 保留区内。

3. 当前双 hart 启动顺序
-----------------------

1. ESP-IDF 二级 bootloader 在 hart0 启动 factory loader。
2. loader 初始化 PSRAM、Flash 线性映射、cache bus、APM/MSPI PMS，并准备
   OpenSBI FDT。
3. loader 释放 hart1 到 IRAM trampoline。hart1 以 a0=1、a1=fdt_addr 进入
   OpenSBI，并在 secondary wait loop 中等待 SBI HSM 启动。
4. hart0 随后以 a0=0、a1=fdt_addr 进入同一个 OpenSBI；fw_jump 明确选择
   hart0 为 cold/boot hart，Linux 也从 hart0 启动。
5. 当前内核命令行默认 maxcpus=1；系统稳定进入用户态后可通过
   /sys/devices/system/cpu/cpu1/online 热插拔启动 hart1。

两个 trampoline 都必须在进入 OpenSBI 前独立完成以下 hart-local 初始化：

- 关闭本 hart M-mode 中断并清除全部 128 个 M CLIC slot 的 IP/IE/ATTR/CTL，
  避免继承 bootloader、ROM 或 blob 留下的 pending/configuration；
- 设置 PMA7：pmaaddr7=0x147fffff、pmacfg7=0xe000001d，覆盖
  0x50000000..0x53ffffff cached PSRAM aperture；
- 清理旧 PMP 配置，再建立允许 Linux S-mode 访问完整地址空间的 RWX
  NAPOT entry。

PMA 是 hart-local。只配置共享 MMU/APM/cache 寄存器不能替代 hart1 的 PMA7；
缺少该项时，hart1 对 0x50000000 的首次 store 会产生 access fault。

4. Cache 与 Sv32 页表
---------------------

OpenSBI 和 Linux RAM 使用 0x50000000 cached PSRAM alias。S31 的 Sv32 page
table walker 不 snoop shared write-back D-cache，因此 Linux head.S 在首次写
satp 前必须对页表所在 PSRAM 执行
ESP32S31_DCACHE_WRITEBACK_LINUX_PSRAM（0x2c000000）。若缺少该 writeback，
软件看到的 PTE 可以正确，而 walker 仍可能读取旧内容并在开启 MMU 后异常。

5. OpenSBI XIP relocation 约束
-----------------------------

fw_base.S 在 boot lottery 之前将 .data 从 Flash LMA 复制到 FW_RW_START，随后
R_RISCV_RELATIVE relocation loop 修正 .data 内的指针。禁止 relocation 后再次
复制 .data；第二次复制会恢复 Flash 中未重定位的原值，可能使
sbi_platform_ops() 通过空指针访问而 fault。

OpenSBI banner 前的 store/AMO access fault 应优先检查 PSRAM MMU、cache bus、
PMA7 和 cache handoff，而不是先归因于 FDT。若异常只在一次刷写后出现，还应
先按 AGENTS.md 的 flash corruption 流程完整擦写、校验并复现。

6. 当前运行边界
---------------

OpenSBI 仍负责 M-mode 启动、SBI HSM 和 reset 等固件服务。Linux 运行期的
跨核 IPI/RFENCE 已走 S-mode native CLIC doorbell，clockevent 走 native
SYSTIMER；不要退回 OpenSBI M-IPI 或让 S-mode 直接访问 local MTIME。中断
模型与本轮稳定性修复详见 s31_clic_clint.txt 和
s31_smode_clic_irq_findings.txt。
