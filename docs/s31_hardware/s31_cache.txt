4.1.3.4 Cache
The ESP32-S31 adopts a cache architecture in which each CPU (Core0 and Core1) has a private instruction
cache, while both CPUs share a unified data cache.
Feature List
• 32KBL1 instruction cache, 64 B block size, two-way set associative
• 64KBL1 data cache, 64 B block size, two-way set associative, supporting write-through and write-back
policies
• Cacheable and non-cacheable access
• Pre-load function
• Lock function
• Critical word first and early restart

Cached regions (0x40000000–0x4FFFFFFF for flash, 0x50000000–0x53FFFFFF for PSRAM)
  require explicit manual cache invalidation and write-back when mixing cached and
  uncached accesses or when handing off between boot stages.

For hart1 cached PSRAM boot, all of the following are required:
  - shared PSRAM MMU entries and shared D-cache DBUS enabled;
  - hart1 private I-cache IBUS enabled;
  - CPU/HP/HP-MEM APM and MSPI PMS permissions;
  - hart-local PMA entry 7 matching ESP-IDF's S31
    esp_cpu_configure_region_protection() setup.
The PMA entry covers 0x50000000..0x53FFFFFF as locked RWX NAPOT
(pmaaddr7=0x147FFFFF, pmacfg7=0xE000001D). Without it, a cached PSRAM access
from hart1 is reported as a PMP/PMA access fault.

OpenSBI and Linux now use the cached 0x50000000 alias. Linux head.S must write
back the page-table writes made by setup_vm() before SATP is loaded because the
S31 Sv32 page-table walker does not snoop the shared write-back D-cache.
